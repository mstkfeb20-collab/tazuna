# 上流の入力（要求・外部設計・業務の説明）

ID 設計の**もとになる文書**の置き場所。設計エージェント（`.github/agents/design-partner.agent.md`）は、ここを読んで設計書のドラフトを書き、各行の根拠にする。ここに書かれていない業務の判断は、ドラフトでは「（案）」になり、人が確かめる。

- 置くもの: 要求（要求仕様・要件定義）、外部設計（ED。画面・帳票・IF の外から見える仕様）、システム設計（SP）、業務の説明（業務フロー・用語・約款の要点）、RDRA などのモデルの書き出し
- 置き方: Markdown にできるものは Markdown で置く（エージェントが読めるように）。Office の文書は、要点を Markdown に起こして置き、元の文書は下の一覧にリンクで残す
- 直す人: 社員。エージェントは読むだけ（`.github/hooks/protected-paths.txt` で守る）
- 置かないもの: ID 設計で決めること（それは docs/design/ の設計書に書く）

## 社外・社内の別の場所にある文書

| 文書 | 版・日付 | 場所 | この案件で使う範囲 |
| --- | --- | --- | --- |
| （例）要求仕様書 | v1.2 2026-10-01 | （SharePoint などのリンク） | 予約・取消・振込の章 |
