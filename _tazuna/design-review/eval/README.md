# 設計書レビュー（base-design-review）の評価セット

tazuna 本体専用（案件では `_tazuna/` ごと削除する）。わざと欠陥を入れた小さな設計書一式で、スキル `.github/skills/base-design-review/` がどれだけ欠陥を拾い、どれだけ誤って指摘するかを測る。

- `design/`・`docs/domain/glossary.md`・`db/schema/`: レビューする設計書一式（予約取消と振込データ取込の書類 10 件・行 61 行）
- `expected.csv`: 欠陥の答え（種別・根拠の行ID）。F18〜F20 は初回の実行で見つかった、答えに入れ忘れていた欠陥
- `decoys.csv`: 問題のない行（それらしいが指摘にしない例：共通の方針に沿った機能ごとの決定、用語集にある言い換えなど）
- `score.py`: 採点。指摘の根拠の行IDが欠陥の行IDと重なれば当たり、種別も合えば種別一致

## 試し方（答えを見せない）

`design/` などの入力とスキル、`scripts/design/catalog.py`・`review_pack.py` だけを別のフォルダに写し、答え（expected.csv・decoys.csv）を見られないエージェントにスキルどおりにレビューさせる。結果の TSV を `score.py` で採点する。スキルの例に、この評価セットの欠陥を書かない（書くと測れなくなる）。
