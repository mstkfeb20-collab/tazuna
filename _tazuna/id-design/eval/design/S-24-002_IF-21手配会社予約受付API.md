# S-24-002 IF定義書：IF-21 手配会社 予約受付API

> 振り分け評価のインプット。設計項目の見出しの下に、1行に1つの決定事項を書く。振り分け先は書かない。

> 対象: S-22-006

## D-06006 リトライと重複実行

- S-24-002-001 手配連携は失敗時に5分おきに3回まで再送する。予約番号で重複を判定するので再送してよい
- S-24-002-002 手配会社から HTTP 409（登録済み）が返ったら、すでに伝わっているものとして成功扱いにする

## D-07004 連携のタイミング・頻度

- S-24-002-003 予約の登録・取消が確定した直後に1件ずつ送る

## D-07006 タイムアウト・リトライ設定

- S-24-002-004 接続タイムアウト5秒、読み込みタイムアウト30秒

## D-07007 相手側障害時の振る舞い

- S-24-002-005 手配会社が止まっていても予約は受け付け、連携待ちとして残して後で送る

## D-07008 項目の対応表

- S-24-002-006 RESERVE.REMARKS → 手配API の note（最大200文字）。超える分は送らない

## D-07011 APIのバージョン・互換性

- S-24-002-007 手配 API は v2 を使う。v1 は2027年3月で停止

## D-07012 スタブ・シミュレータ

- S-24-002-008 開発と試験では、手配 API をスタブで置き換え、409・タイムアウト・500 を再現できるようにする

## D-07013 相手システムの仕様書

- S-24-002-009 手配会社 予約受付API仕様書 v2.3 を正とする

## D-09005 再試行してよいエラー

- S-24-002-010 接続タイムアウトと HTTP 503 は再送してよい。HTTP 400 は再送しない

## D-09009 タイムアウト時の扱い

- S-24-002-011 手配 API がタイムアウトしたら、登録されたか分からないので照会 API で確かめてから再送する
