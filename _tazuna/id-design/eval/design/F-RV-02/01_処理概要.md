# F-RV-02 予約登録 — 処理概要

> 振り分け評価のインプット。1行に1つの決定事項を書く。設計項目や振り分け先は書かない。

- D-RV02-0101 F-RV-02 予約登録。ツアー詳細画面から遷移し、人数と代表者の情報を入力して予約を確定する
- D-RV02-0102 お客様が Web で、窓口担当が店頭で来店・電話のお客様に代わって予約を入力する
- D-RV02-0103 予約を確定した時点で席を押さえ、振込期限までに入金してもらう
- D-RV02-0104 ツアー詳細画面の［このツアーを予約する］で予約入力画面を開く
- D-RV02-0105 予約確認画面の［予約を確定する］で ReservationService#reserve を呼ぶ
- D-RV02-0106 入力はツアーコード・大人人数・子供人数・代表者情報・備考・パスポートの写し・受付トークン
- D-RV02-0107 出力は予約番号・合計金額・振込期限・振込先口座
- D-RV02-0108 お客様は会員としてログインしていること。窓口担当は社内SSOでログインしていること
- D-RV02-0109 予約は出発日の7日前まで受け付ける。6日前以降は受け付けない
- D-RV02-0110 予約が登録されたときは、ツアーの残席数が予約人数分だけ減っている
- D-RV02-0111 予約が登録されたときは、手配会社への連携待ちが1件登録されている
- D-RV02-0112 予約が登録されたときは、代表者のメールアドレスあてに予約受付メールの送信が依頼されている
- D-RV02-0113 予約の確定は 入力の再検査 → 残席の確保 → 予約の登録 → 手配連携待ちの登録 → 受付メールの送信依頼 の順に行う
- D-RV02-0114 受付メールの送信依頼は予約の登録をコミットした後に行い、送信に失敗しても予約は取り消さない
- D-RV02-0115 残り1席に2件の予約が同時に確定されたときは、1件だけ成功し、もう1件は残席不足になる
- D-RV02-0116 同じ受付トークンで再送された確定要求は、二重に登録せず最初の登録結果を返す
- D-RV02-0117 残席は検索結果や入力画面の表示時点ではなく、予約を確定する時点で厳密に判定する
- D-RV02-0118 予約登録の issue では docs/requirements/reservation.md の REQ-001 を読む
