# S-33-001 移行設計書：移行設計書

> 振り分け評価のインプット。設計項目の見出しの下に、1行に1つの決定事項を書く。振り分け先は書かない。

## D-17001 データ移行の対応表

- S-33-001-001 旧システムの入金区分 'N'（未入金）は TRANSFER 0、'Y'（入金済）は 1、取消フラグが立った予約は 9 に移す

## D-17002 移行データの検証

- S-33-001-002 移行前後で、予約件数・合計金額の総額・ツアーごとの残席数が一致すること

## D-17003 並行稼働

- S-33-001-003 移行後2週間は、旧システムでも同じ予約を登録して結果を突き合わせる

## D-17004 既存APIとの互換

- S-33-001-004 旧システムの予約照会 API を使う提携サイトのため、同じ応答項目を返す API を残す

## D-17005 既存データの不整合

- S-33-001-005 旧システムで残席がマイナスのツアーは、移行前に予約担当が個別に補正する
