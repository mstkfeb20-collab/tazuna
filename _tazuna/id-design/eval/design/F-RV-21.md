# F-RV-21 手配会社への予約連携

> 振り分け評価のインプット。1行に1つの決定事項を書く。設計項目や振り分け先は書かない。

## 機能構成・処理概要

- D-RV21-001 F-RV-21 手配会社連携。予約の登録と取消を、宿とバスを手配する手配会社に伝える

## トランザクション・整合性

- D-RV21-002 手配会社への連携に失敗したまま取消された予約は、取消連携を送って手配を解除させる
- D-RV21-003 手配連携は失敗時に5分おきに3回まで再送する。予約番号で重複を判定するので再送してよい

## 外部インタフェース・連携

- D-RV21-004 IF-21: 手配会社の予約受付 API（REST・JSON）。登録と取消の2種類
- D-RV21-005 予約の登録・取消が確定した直後に1件ずつ送る
- D-RV21-006 手配会社から HTTP 409（登録済み）が返ったら、すでに伝わっているものとして成功扱いにする
- D-RV21-007 接続タイムアウト5秒、読み込みタイムアウト30秒
- D-RV21-008 手配会社が止まっていても予約は受け付け、連携待ちとして残して後で送る
- D-RV21-009 RESERVE.REMARKS → 手配API の note（最大200文字）。超える分は送らない
- D-RV21-010 手配 API は v2 を使う。v1 は2027年3月で停止
- D-RV21-011 開発と試験では、手配 API をスタブで置き換え、409・タイムアウト・500 を再現できるようにする
- D-RV21-012 手配会社 予約受付API仕様書 v2.3 を正とする

## 例外・エラー処理

- D-RV21-013 接続タイムアウトと HTTP 503 は再送してよい。HTTP 400 は再送しない
- D-RV21-014 手配 API がタイムアウトしたら、登録されたか分からないので照会 API で確かめてから再送する

## テスト

- D-RV21-015 手配会社の検証環境と、登録・取消・再送の一連を通しで確かめる
