# 共通設計（全機能に適用）

> 振り分け評価のインプット。1行に1つの決定事項を書く。設計項目や振り分け先は書かない。

## 機能構成・処理概要

- D-CM-001 画面制御（Controller）・ユースケース（Service）・ドメイン（業務ルール）にクラスを分ける
- D-CM-002 取消料率・残席の確保などの業務ルールは domain 層に置き、画面制御やSQLに書かない
- D-CM-003 日数の計算は共通部品 BusinessCalendar を使い、各機能で日付を直接引き算しない

## 画面・UI

- D-CM-004 一覧は左寄せ、主要なボタンは画面の右下に置く
- D-CM-005 入力欄には必ず label を付け、色だけでエラーを伝えない
- D-CM-006 画面・メッセージ・帳票では「取消」で統一し、「キャンセル」は使わない
- D-CM-007 「振込済」は「入金済」と書かない。銀行振込以外の入金手段がないため
- D-CM-008 エラーは項目の直下に赤字で出し、画面上部に件数をまとめて出す
- D-CM-009 日付は yyyy/MM/dd、金額は3桁区切りに「円」を付けて表示する

## 入力チェック

- D-CM-010 単項目 → 相関 → マスタ → 業務 の順に検査し、単項目でエラーがあればその先は検査しない
- D-CM-011 画面での検査は入力補助とし、サーバ側で必ず同じ検査をやり直す
- D-CM-012 金額は整数・0以上。小数や負の値は受け付けない
- D-CM-013 入力チェックのエラーごとにメッセージIDを1つ決め、同じエラーには同じIDを使う
- D-CM-014 前後の空白を除き、全角数字は半角にしてから検査する

## 業務ロジック

- D-CM-015 取消料率表・予約締切日数は設定テーブルで持ち、コードに数値を書かない
- D-CM-016 営業日は銀行の営業日に合わせる。全機能で同じ暦を使う
- D-CM-017 金額の1円未満は、特に決めがなければ切り捨てる

## データ・DB

- D-CM-018 業務データは論理削除とし、物理削除は保持期間を過ぎた退避処理だけで行う
- D-CM-019 全テーブルに 作成者・作成日時・更新者・更新日時 を持たせる
- D-CM-020 DB の文字コードは AL32UTF8 とする
- D-CM-021 エンティティの桁数・NULL 可否は DDL と一致させる
- D-CM-022 SQL は文字列連結で組み立てない

## トランザクション・整合性

- D-CM-023 トランザクションはユースケース（Service）のメソッド単位で張る
- D-CM-024 複数テーブルを更新するときは TOURINFO → RESERVE の順に更新する
- D-CM-025 分離レベルは READ COMMITTED とする
- D-CM-026 画面処理のトランザクションは1秒以内に終える

## 例外・エラー処理

- D-CM-027 業務エラーは BusinessException、想定外の障害は SystemException を継承する
- D-CM-028 例外を catch してよいのは画面制御層と共通ハンドラだけ
- D-CM-029 業務エラーはメッセージを出して同じ画面に留まり、システムエラーは共通エラー画面に遷移する
- D-CM-030 空の catch ブロックは書かない
- D-CM-031 定義にない区分値を受け取ったら業務エラーにし、処理を進めない
- D-CM-032 メッセージIDは <種別>-<業務>-<連番3桁>。例 E-RV-032

## メッセージ・ログ

- D-CM-033 何が起きたか・なぜか・どうすればよいか の3つを書く
- D-CM-034 業務エラーは WARN、システムエラーは ERROR で出す
- D-CM-035 すべてのログに 相関ID・利用者ID・機能ID を出す
- D-CM-036 氏名・電話番号・メールアドレスはログに伏せ字で出す
- D-CM-037 アプリケーションログは90日、操作ログは7年保存する
- D-CM-038 ERROR で出すメッセージIDは、すべて監視定義に登録する
- D-CM-039 System.out / System.err に出さず、必ずロガーを使う
- D-CM-040 スタックトレースは利用者の画面に出さず、ログにだけ出す

## セキュリティ

- D-CM-041 窓口担当は社内SSO、お客様は会員IDとパスワードでログインする
- D-CM-042 画面に出す値は必ずエスケープする
- D-CM-043 SQL にはバインド変数を必ず使う
- D-CM-044 更新系のリクエストには CSRF トークンを必須にする
- D-CM-045 手配 API の認証キーは秘密管理サービスから読み、コードや設定ファイルに書かない
- D-CM-046 通信は TLS1.2 以上。会員のパスワード以外に暗号化して保持する項目はない
- D-CM-047 パスワードは bcrypt で保存し、再設定用のトークンは30分で無効にする
- D-CM-048 重大な脆弱性のある依存ライブラリがあればビルドを止める
- D-CM-049 ログインしたらセッションIDを再発行する

## 性能・容量

- D-CM-050 一覧の取得では、ループの中で SQL を発行しない
- D-CM-051 1万件を超える可能性がある取得は、全件をメモリに載せずに順に処理する

## アーキテクチャ・共通方針

- D-CM-052 domain は application・infrastructure に依存しない
- D-CM-053 業務領域（tour・reservation・transfer）ごとにパッケージを分ける
- D-CM-054 クラス名・項目名は業務用語集の英名に合わせる（予約 Reservation、振込状況 TransferStatus）
- D-CM-055 許可リストにない依存ライブラリは追加しない
- D-CM-056 java.util.Date と System.exit は使わない
- D-CM-057 共通部品は Money（金額）・BusinessCalendar（営業日）・CodeValue（区分値）
- D-CM-058 依存はコンストラクタインジェクションだけで受け取る
- D-CM-059 手配 API の URL とタイムアウト値は設定ファイルに置く
- D-CM-060 コメントには「なぜ」だけを書き、処理の言い換えは書かない
- D-CM-061 フォーマッタの設定ファイルに従う

## テスト

- D-CM-062 テストデータはテストごとに作り、終わったら消す
- D-CM-063 テストには対応する要件IDを @Tag("REQ-xxx") で付ける
- D-CM-064 domain 層の分岐網羅は90%以上
- D-CM-065 DB は偽物にせず本物を使う。外部 API だけスタブにする
- D-CM-066 テストは実装を見ずに要件から作る
- D-CM-067 テストの削除と @Disabled は人が判断する

## 運用・保守

- D-CM-068 画面のエラー率が5分間で1%を超えたら通知する
- D-CM-069 問い合わせは相関IDで画面・API・バッチのログを追う
- D-CM-070 月初に、保持期間を過ぎた一時ファイルを削除する
- D-CM-071 DB を変えるリリースには、戻すためのスクリプトを用意する
- D-CM-072 取消料率表などの設定変更も、コードと同じくレビューを通す
- D-CM-073 運用手順書は社内の運用ポータル「ツアー予約」ページにある
- D-CM-074 改修の影響範囲は himotoki で要求から候補を出して確かめる

## 移行・互換性

- D-CM-075 旧システムから持ち込むコードの既存違反はベースラインに記録し、新しいコードでは禁止する

## 開発作業・AI運用

- D-CM-076 エージェントには本番DBへの接続・強制 push・reset --hard をさせない
- D-CM-077 要件・不変条件・base スキル・共通 Lint はエージェントに編集させない
- D-CM-078 --no-verify や Lint の無効化でチェックを飛ばさせない
- D-CM-079 ソースや予約データを、許可されていない外部サービスに送らせない
- D-CM-080 Lint・テスト・完了条件のテストがすべて通ったら完了とする
- D-CM-081 PR には実行したコマンドと結果を添える
- D-CM-082 新しいユースケースは ReservationService#reserve を手本にする
- D-CM-083 設計に書かれていないことは推測で埋めず、質問として PR に書く
- D-CM-084 旧システムの設計書からの業務ルールは base-spec-extraction で候補にし、予約担当の承認を得る
