# 振り分けの評価セット（ツアー予約）

ID設計を1行1決定事項で書いた md（インプット）と、各行の正しい振り分け先（正解）の組です。振り分けを行うスクリプトやスキルを作ったら、ここで行ごとの正解率を測ります。

題材はツアー予約です。himotoki の評価用設計書（`samples/spec-extraction`）、tazuna の Java 見本（`src/`）と同じ業務ルールを使っています。

## 中身

| ファイル | 内容 | 振り分ける側に見せるか |
| --- | --- | --- |
| `design/common.md` | 全機能に共通する設計（84行） | 見せる |
| `design/F-RV-01.md` 〜 `F-RV-41.md` | 機能ごとの設計（8機能・138行） | 見せる |
| `expected.csv` | 正解。行ごとの設計項目・4属性・振り分け先・置き場所・持ち主 | **見せない** |
| `source.py` | インプットと正解の正本（行・設計項目・属性の上書き） | **見せない** |
| `build_eval.py` | `source.py` から `design/` と `expected.csv` を作る | — |

### 機能

| 機能ID | 機能 | 主に試す観点 |
| --- | --- | --- |
| F-RV-01 | ツアー検索 | 画面・性能・キャッシュ |
| F-RV-02 | 予約登録 | 入力チェック・計算・DB・排他・冪等性 |
| F-RV-03 | 予約取消 | 取消料・状態遷移・認可・操作ログ |
| F-RV-04 | 予約照会 | 表示条件・データの認可・保持期間 |
| F-RV-11 | 振込データ取込（夜間バッチ） | ジョブ・ファイル連携・突合・再実行 |
| F-RV-21 | 手配会社への予約連携 | 外部API・リトライ・補償処理 |
| F-RV-31 | 予約一覧表（日次帳票） | 帳票・集計・出力権限 |
| F-RV-41 | 旧予約システムからのデータ移行 | 移行・互換・既存データ |

振り分け表（`../ID設計項目の振り分け表.xlsx`）の198項目は、すべて1行以上インプットに現れます。Excel の「例」列は、インプットの行から1つずつ取っています。

## 正解の決め方

- 各行に、振り分け表の設計項目を1つ割り当てます。属性は既定でその項目の属性を使います。
- 行の中身が項目の既定と違うときは、その行だけ属性を上書きします（33行）。多くは適用範囲です。共通ファイルに書いた全機能共通のルールや、機能ファイルに書いた機能固有の値がこれに当たります。`expected.csv` の「備考」列に、既定と何が違うかを書いています。
- 振り分け先・置き場所・持ち主は、4属性から `build.py` の `map_item()`（Excel の数式と同じルール）で決めます。

上書きした33行は、設計項目の名前だけを見て振り分けると外れます。振り分けが中身を読んでいるかは、ここで分かります。

## 採点の考え方（ツールを作るときの目安）

- **主の一致率**：振り分け先（主）が正解と一致した行の割合。最も重要な指標です。
- **属性ごとの一致率**：性質・機械検査・適用範囲・業務承認のどれで外れたかを見ると、判定基準のどこが曖昧かが分かります。
- **上書き行の一致率**：33行だけで測ります。
- **外れた行の見直し**：外れた行は「判定基準が足りない」「設計の書き方が曖昧」「正解が間違い」のどれかに分けます。正解が間違いなら `source.py` を直します。

## 作り直す

```bash
python3 _tazuna/id-design/eval/build_eval.py   # design/ と expected.csv
python3 _tazuna/id-design/build.py             # 振り分け表（Excel）
```

`build_eval.py` は、設計項目名の誤り、インプットに現れない項目、Excel の例とインプットのずれを見つけると、終了コード1で止まります。
