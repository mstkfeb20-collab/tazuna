# 振り分けの評価セット（ツアー予約）

ID 設計を、ドキュメント体系（`../ドキュメント体系.md`）の書類ごとに書いたもの（インプット）と、各行の正しい置き場所・振り分け先（正解）の組です。振り分けのスクリプトやスキル、置き場所の検査（Lint）を作ったら、ここで行ごとに採点します。

題材はツアー予約です。himotoki の評価用設計書（`samples/spec-extraction`）、tazuna の Java 見本（`src/`）と同じ業務ルールを使っています。

## 中身

| ファイル | 内容 | 振り分ける側に見せるか |
| --- | --- | --- |
| `design/S-xx-nnn_名前.md`（34ファイル） | 書類1つにつき1ファイル。506行 | 見せる |
| `expected.csv` | 正解。行ごとの正しい書類・設計項目・3属性・振り分け先・置き場所・持ち主 | **見せない** |
| `source.py` | インプットと正解の正本 | **見せない** |
| `build_eval.py` | `source.py` から `design/` と `expected.csv` を作り、整合を検査する | — |

### 書類の書き方

```markdown
# S-21-002 画面設計書：予約入力・確認・完了画面

## D-02002 画面項目定義

- S-21-002-006 予約確認画面には、入力内容・合計金額とその内訳…を表示する
- S-21-002-007 予約完了画面には、予約番号・振込期限・振込先口座を表示する
```

- ファイルは書類実体ごとです。書類実体ID `S-21-002` は、書類ID `S-21`（画面設計書）の2つ目という意味で、番号に業務の意味はありません。
- 見出しは設計項目の項番と名前です。その書類の記載項目（`../documents.py`）にある項目だけを使えます。
- 行IDは `書類実体ID-通し番号3桁` です。通し番号はファイルの中で閉じています。
- 番号は付けたら変えません。追加はファイルの末尾の番号で行い、途中に挿入して振り直すことはしません。使わなくなった行の番号も消しません。
- 別の書類に移すときは、元の行を廃止として残し、移った先で新しい番号を付けます。

| 区分 | 書類 | ファイル | 行 |
| --- | --- | --- | --- |
| 共通設計 | 機能一覧・方式・画面共通・メッセージ・セキュリティ・コード・共通部品・バッチ共通・非機能（各1） | 9 | 111 |
| 共通設計 | テーブル定義書（TOURINFO・RESERVE・TRANSFER_IMPORT） | 3 | 44 |

## 正解の決め方

- **振り分け先**：正しい設計項目の3属性（性質・機械検査・業務承認）から、`build.py` の `map_item()` で決めます。Excel の数式と同じルールです。
- **置き場所・持ち主**：振り分け先と、正しい書類の区分（共通設計・開発運用か、機能別設計か）から `place_owner()` で決めます。
- **属性の上書き（16行）**：行の中身が設計項目の既定と違うときだけ、その行の属性を上書きしています。例えば「会員番号：窓口担当が入力するときは必須」は、必須・任意の既定（値・形式、静的に可）と違い、条件付きなので振る舞い・実行で可です。`expected.csv` の「備考」列に違いを書いています。
- **書く場所の間違い（9行）**：評価のため、わざと違う見出しや書類に書いた行です。正解には正しい書類と設計項目を入れています。

| 判定 | 行数 | 例 |
| --- | --- | --- |
| 項目違い（同じ書類の別の見出しに書いた） | 7 | 「取消料は1円未満を切り捨てる」を計算式の下に書いた（正しくは端数処理） |
| 書類違い（別の書類に書いた） | 2 | 「大人人数と子供人数の合計は9人まで」を画面設計書の画面項目定義に書いた（正しくは処理設計書の相関チェック） |

## 採点の考え方（ツールを作るときの目安）

書く人が書類と設計項目を選ぶので、振り分け先そのものは項目から機械的に決まります。ツールの仕事は次の2つです。

- **置き場所の検査**：9行の間違いを見つけられるか。見つけた行に、正しい書類と設計項目を示せるか。正しい497行を間違いと言わないか。
- **属性の例外の検出**：16行の上書きを見つけられるか。上書きのない行で、余計な上書きを出さないか。

外れた行は「判定基準が足りない」「書き方が曖昧」「正解が間違い」のどれかに分けます。正解が間違いなら `source.py` を直します。

## 作り直す

```bash
python3 _tazuna/id-design/build.py             # 振り分け表（Excel）とドキュメント体系.md
python3 _tazuna/id-design/eval/build_eval.py   # design/ と expected.csv
```

`build_eval.py` は、記載項目にない見出し、インプットに現れない設計項目、Excel の例とのずれなどを見つけると、終了コード1で止まります。
