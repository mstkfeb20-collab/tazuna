# ドキュメント体系（ID 設計）

> `build.py` が `documents.py` から生成します。直接編集しないでください。正本は Excel（`ID設計項目の振り分け表.xlsx`）です。

ID 設計は2段で決めます。

1. **書類一覧**：どんな書類を、どの単位で作るか（`S-xx`）
2. **記載項目**：その書類に、どの設計項目（`D-ccsss`）を書くか

書類IDの十の位は区分です（1 共通設計、2 機能別設計、3 開発・運用）。設計項目の項番は `D-` + 観点2桁 + 通し番号3桁です。

## 書類の書き方

- 1つの書類実体を1ファイルにします（例 `docs/design/S-22-005_振込データ取込.md`）。書類実体IDの3桁に意味は持たせません。
- 見出しは `## D-ccsss 設計項目名`。その書類の記載項目にある項目だけを使います。
- 行は `- 書類実体ID-通し番号3桁 本文`。番号は付けたら変えず、追加は末尾の番号で行い、使わなくなった行も消さずに「（廃止）」と書きます。
- 書類実体は `docs/design/書類一覧.md` の表（書類実体ID・書類・名前・機能）に1行ずつ載せます。機能一覧（S-10）を作るときに一緒に作ります。
- 機能別設計の書類は処理設計書（S-22）を中心にまとまります。テスト仕様書・画面・ジョブ・IF・帳票は、書類一覧の「機能」にその書類を使う処理設計書を書きます（複数可）。転記ツールは要件と作業一覧をその処理設計書のファイルにまとめます。
- 機能どうしの影響（ある機能を変えると別の機能も変わる）は書類一覧に書きません。テスト仕様書の回帰テストの範囲と himotoki で扱います。
- 行の中身が設計項目の既定の属性と違うときだけ、行末に `{性質:振る舞い 機械検査:実行で可}` のように書きます。
