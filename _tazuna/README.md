| [id-design/eval/](id-design/eval/) | 振り分けの評価セット。ツアー予約の ID 設計をドキュメント体系の書類ごとに書いたもの（34ファイル・506行）と、行ごとの正解 |

### ID 設計の Excel の使い方

- 各設計項目には3つの属性（性質・機械検査・業務承認）だけを付ける。振り分け先は属性から、置き場所と持ち主は属性と書類の区分（共通か機能別か）から数式で決まる。人が振り分け先を直接書かないので、個人に依存しない。
- 属性の選び方は「属性の判定基準」シートの問いに答えて決める。この問いを手順にすれば、振り分けをスキルにできる。
- 項目や属性を直すときは `docs/design/ID設計.xlsx` を直し、`python3 scripts/design/id_design.py export` で書き出しも作り直す。

## 案件のリポジトリでは削除する

```bash
git rm -r _tazuna
```

このフォルダがあると、hooks が型のファイル（base スキル・共通Lint・hooks・CIなど）の編集を許可します。tazuna 本体を改善するための仕組みなので、案件では必ず削除してください。

## 指南書を更新するとき

- 指南書は人が読む資料です。エージェント向けの指示は `AGENTS.md` と `.github/skills/` に書きます。
- テンプレートの実ファイル（ひな形）の内容を指南書に複製しないでください。リンクで参照します。
