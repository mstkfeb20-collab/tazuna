# _tazuna/（tazuna 本体専用）

このフォルダは tazuna 本体の説明資料と、テンプレート本体であることを示す印を兼ねています。**テンプレートの一部ではありません。**

| ファイル | 内容 |
| --- | --- |
| [guide.md](guide.md) | 新規プロジェクト向け ハーネス導入指南書（考え方・役割分担・立ち上げ手順・運用） |
| [id-design/ID設計項目の振り分け表.xlsx](id-design/) | ID（内部設計）相当の設計項目198件と、各項目を「機械（設計・Lint・テスト・hooks）／AIへの条件／人のための設計／知識」に振り分けた表（叩き台・レビュー中） |
| [id-design/build.py](id-design/build.py) | 振り分け表を作り直すスクリプト（`python3 _tazuna/id-design/build.py`） |

### 振り分け表の使い方

- 各設計項目には4つの属性（性質・機械検査・適用範囲・業務承認）だけを付ける。振り分け先・tazuna での置き場所・持ち主は、属性から数式で自動的に決まる。人が振り分け先を直接書かないので、個人に依存しない。
- 属性の選び方は「属性の判定基準」シートの問いに答えて決める。この問いを手順にすれば、振り分けをスキルにできる。
- 項目や属性を直すときは `build.py` を編集して作り直す。Excel を直接直した場合は、`build.py` にも反映する。

## 案件のリポジトリでは削除する

```bash
git rm -r _tazuna
```

このフォルダがあると、hooks が型のファイル（base スキル・共通Lint・hooks・CIなど）の編集を許可します。tazuna 本体を改善するための仕組みなので、案件では必ず削除してください。

## 指南書を更新するとき

- 指南書は人が読む資料です。エージェント向けの指示は `AGENTS.md` と `.github/skills/` に書きます。
- テンプレートの実ファイル（ひな形）の内容を指南書に複製しないでください。リンクで参照します。
